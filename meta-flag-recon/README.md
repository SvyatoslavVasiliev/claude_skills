# meta-flag-recon

Инструментарий для инвентаризации фича-флагов и экспериментов в отгружаемом
фронтенде `instagram.com` и `facebook.com` — и для превращения этого инвентаря
в набор продуктовых гипотез.

Работает только с тем, что Meta сама отдаёт браузеру: HTML-документ, JS-бандлы,
GraphQL-трафик собственной сессии. Никакого обхода авторизации, никаких чужих
аккаунтов, никакого скрейпинга пользовательских данных.

## Почему это не запущено, а отдано как инструмент

Сессия, в которой это собрано, работает за egress-прокси, который отдаёт `403`
на всё, кроме GitHub и пакетных реестров: `www.instagram.com`,
`static.cdninstagram.com`, `www.facebook.com`, `static.xx.fbcdn.net` —
все заблокированы (и для `curl`, и для серверного веб-фетча). Живые бандлы
скачать было невозможно, поэтому вместо выдуманного списка флагов здесь лежит
код, который соберёт настоящий список за один вечер на вашей машине.

Парсер проверен на фикстурах, воспроизводящих реальную форму бандлов Meta
(`tests/fixtures`, `make test`).

## Как устроены флаги у Meta

Знать это до запуска важнее, чем сам запуск: половина ожиданий от такой
разведки разбивается о то, что имена флагов в проде вырезаны.

| механизм | как выглядит в бандле | читаемость |
|---|---|---|
| **GK** (Gatekeeper) | `require("gkx")("25102")` | **имя вырезано**, остаётся числовой id; значение для вашей сессии лежит в `gkxData` в HTML |
| **QEX** (QuickExperiment) | `require("qex")._("ig_web_reels_ad_density_v2")` | часто **читаемый ключ** — самая ценная строка в выдаче |
| **Relay provider** | `__relay_internal__pv__PolarisXrelayprovider` | читаемое имя + разрешённое значение видно прямо в переменных GraphQL-запроса |
| **имя модуля** | `__d("PolarisReelsAdsSurfaceRoot", …)` | не минифицируется — главный источник смысла |
| **события логгера** | `"instagram_web_reels_ad_impression"` | читаемые — показывают, *какую метрику* двигают |
| **роуты** | `PolarisRoutes`, `CometRoute*` | новые URL появляются здесь до того, как на них есть ссылка в UI |

Ключевая мысль: сам по себе `gkx("25102")` не значит ничего. Значение ему даёт
**модуль, в котором он вызван**, и **факт переключения** между снапшотами.

## Быстрый старт

```bash
# 0. один раз: залогиниться руками, профиль сохранится
node collect.mjs --site instagram --out snapshots/ig-$(date +%F) --profile ~/.mfr/ig --headed

# 1. дальше можно headless
node collect.mjs --site facebook --out snapshots/fb-$(date +%F) --profile ~/.mfr/fb

# 2. разобрать снапшот в инвентарь
python3 mfr.py extract snapshots/ig-$(date +%F)
python3 mfr.py report  snapshots/ig-$(date +%F) > reports/ig-$(date +%F).md

# 3. главное — дифф двух снапшотов: это и есть дорожная карта
python3 mfr.py diff snapshots/ig-2026-08-04 snapshots/ig-2026-08-18 > reports/ig-diff.md

# 4. разрешить найденные флаги на живой сессии и сравнить два аккаунта
node probe.mjs --inventory snapshots/ig-$(date +%F)/inventory.json \
  --url https://www.instagram.com/ --profile ~/.mfr/ig --out probes/ig-a.json
node probe.mjs --inventory snapshots/ig-$(date +%F)/inventory.json \
  --url https://www.instagram.com/ --profile ~/.mfr/ig-second --out probes/ig-b.json
python3 probe-diff.py probes/ig-a.json probes/ig-b.json snapshots/ig-$(date +%F)/inventory.json
```

Требования: Node 18+ с `playwright` (`npm i playwright && npx playwright install chromium`)
и Python 3.10+ (только стандартная библиотека).

## Файлы

| файл | что делает |
|---|---|
| `collect.mjs` | водит реальный Chromium по списку поверхностей, сохраняет все JS-бандлы, HTML и GraphQL-трафик в снапшот |
| `mfr.py extract` | режет бандлы по границам `__d("Module")` и приписывает каждый флаг модулю, который его читает |
| `mfr.py report` | markdown-отчёт: где сосредоточено гейтирование, читаемые QEX-ключи, разрешённые GK, что логируется |
| `mfr.py diff` | дифф двух снапшотов: новые модули, новые GK, **переключившиеся GK**, новые запросы, новые роуты |
| `probe.mjs` | спрашивает у живой страницы значения найденных флагов для текущего аккаунта |
| `probe-diff.py` | флаги, которые разошлись между двумя аккаунтами = активный сплит, а не завершённый роллаут |
| `PLAYBOOK.md` | как из инвентаря получить гипотезы, и чего в нём принципиально нет |

## Покрытие

Полнота определяется списком поверхностей в `ROUTES` внутри `collect.mjs`, а не
глубиной скролла: чанки грузятся лениво, и непосещённая поверхность просто не
приедет. Добавляйте туда всё, что вас интересует, включая страницы настроек —
там непропорционально много свежих флагов.
