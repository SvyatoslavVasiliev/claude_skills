# Как сделать так, чтобы Claude выполнял это сам

Автономность здесь упирается в три разные преграды, и лечатся они
разным. Путать их — главная ошибка: настройкой снимается только первая.

| Преграда | Чем лечится | Кто делает |
|---|---|---|
| 1. Сеть до `avito.ru` закрыта политикой окружения | настройка облачного окружения | вы, один раз |
| 2. Датацентровый нероссийский IP — Avito режет такие диапазоны | **не лечится настройкой**, нужен запуск с вашей машины | вы, один раз |
| 3. Капча — нужен человек, чтобы нажать | один ручной проход, дальше cookie в `.browser-profile/` | вы, один раз |

Отсюда вывод: **облачная сессия автономной не станет даже с открытой
сетью** — упрётся в 2 и 3. Автономность даёт только локальный запуск.
Зато там снимаются все три сразу.

## Разовая настройка (15 минут)

Claude Code локально — CLI в терминале, десктоп-приложение или расширение
для IDE. Установите, откройте этот репозиторий, дальше:

```bash
cd avito-chess-hunter
python3 -m pip install playwright pyyaml && python3 -m playwright install chromium

# ЕДИНСТВЕННЫЙ шаг, где нужен человек: пройти капчу в окне браузера
./run.sh --headful --max-pages 2
```

Cookie после этого лежит в `.browser-profile/` и переживает перезапуски.
С этого момента прогоны идут без вас.

**Права придётся прописать самому.** Этого файла в репозитории нет
намеренно: Claude не может выписывать себе разрешения, попытка
закоммитить его отклоняется. Создайте `.claude/settings.json` в КОРНЕ
репозитория (на уровень выше этой папки):

```json
{
  "permissions": {
    "allow": [
      "Bash(./run.sh:*)",
      "Bash(python3 scrape.py:*)",
      "Bash(python3 score.py:*)",
      "Bash(python3 fetch_photos.py:*)",
      "Read(avito-chess-hunter/photos/**)",
      "Read(avito-chess-hunter/debug/**)"
    ]
  }
}
```

Без него всё работает, просто Claude будет спрашивать разрешение на каждый
запуск. Мешает только в cron, где спросить некого. `/permissions` в сессии
покажет, что ещё добавить.

**Важно про каталоги.** Файл прав — единственное, что лежит в корне.
Все остальные команды запускаются из `avito-chess-hunter/`:

```
claude_skills/                  <- корень, здесь .claude/settings.json
└── avito-chess-hunter/         <- здесь всё остальное, команды отсюда
```

## Дальше Claude делает всё сам

```bash
./run.sh
```

Один вызов: сбор → ранжирование → скачивание фото по шортлисту.
Затем в сессии Claude Code достаточно сказать:

> разбери shortlist.csv и photos/ по vision_prompt.md и markers.yaml

и он прогонит разбор фотографий, сопоставление с маркерами, выдаст
таблицу с вердиктами и готовые тексты вопросов продавцам.

## По расписанию, без вас вообще

Лоты уходят за часы, поэтому смысл есть только в регулярном прогоне.

**macOS / Linux** — в `crontab -e`:

```cron
# каждый день в 8:47 (не в 9:00: на круглых минутах пик нагрузки)
47 8 * * * cd ~/claude_skills/avito-chess-hunter && ./run.sh >> run.log 2>&1
```

Чтобы Claude сразу и разбирал результат, добавьте вторым шагом
неинтерактивный вызов:

```cron
52 8 * * * cd ~/claude_skills && claude -p "Прогони avito-chess-hunter/run.sh, \
затем разбери shortlist.csv и photos/ по vision_prompt.md и markers.yaml. \
Пришли только лоты с вердиктом gem или maybe, с обоснованием по каждому." \
>> ~/avito-chess.log 2>&1
```

**Windows** — Task Scheduler, действие `bash -lc "cd ... && ./run.sh"`
(через WSL) либо прямой вызов `python scrape.py` в `cmd`.

## Если всё-таки хочется в облаке

Открыть сеть: меню облачного окружения в заголовке сессии → Edit →
Network access, добавить `avito.ru`. Плюс `sovietchesssets.com` и
`barnebys.com` — они нужны, чтобы дозаполнить пробелы в `markers.yaml`
(паттерн «Баку», цены по холмогорской кости).

Честная оценка: на Avito это, скорее всего, разобьётся о преграды 2 и 3.
Попытка стоит пяти минут, планировать под неё не стоит. А вот для двух
коллекционерских сайтов открытие сети сработает наверняка — и это
единственная часть задачи, которую облачная сессия закроет полностью
сама.

## Чего автоматизация не даст никогда

Окончательной атрибуции по фото. Решающие признаки физические — способ
утяжеления, фактура сукна, столярка коробки, линии Шрегера на кости.
Конвейер отвечает на вопрос «кого спросить и о чём», а решение о покупке
остаётся за осмотром. Это ограничение метода, а не настройки.

## Если что-то не ставится

**`playwright: command not found`** — самая частая. CLI ставится в каталог
скриптов Python, которого нет в `PATH`. Вызывайте через модуль, тогда
интерпретатор находит его сам:

```bash
python3 -m playwright install chromium
```

**`No module named playwright` при том, что pip отчитался об установке** —
`pip` и `python3` это разные интерпретаторы. Ставьте тем же, которым
запускаете:

```bash
python3 -m pip install playwright pyyaml
```

**Проверка, что всё на месте:**

```bash
python3 -m playwright --version     # должна быть версия, не ошибка
python3 -c "import yaml; print('yaml ok')"
```

**Windows** — вместо `python3` пишите `python` или `py -3`.

**Чисто, чтобы не ломать системный Python** (рекомендуется):

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
python3 -m pip install playwright pyyaml
python3 -m playwright install chromium
```

## Про блокировку Avito — читать до первого полного прогона

Avito закрывается на 4-5 странице при быстрой глубокой пагинации. Это не
баг, это работающая защита, и полностью её не обойти: на той стороне
работают люди, которым за это платят. Что сделано и чего ждать.

**Форма обхода изменена на мелко-широкую.** Было: один запрос, страницы
1,2,3...50 подряд — самый яркий признак бота. Стало: 3 страницы на
запрос, порядок запросов случайный, пауза 20 сек с разбросом.

Побочно это собирает более полезное. Сортировка по дате, лоты уходят за
часы — значит страница 40 старого запроса мертва, а ценность сидит в
первых страницах МНОГИХ запросов. Редкий случай, когда ограничение и
польза указывают в одну сторону.

**При блокировке скрипт отступает, а не падает:** паузы 2 / 5 / 15 минут,
после четвёртой блокировки подряд останавливается. Собранное уже в
`items.jsonl`, повторный запуск продолжает с места остановки — прерывать
можно свободно.

**Реалистичные ожидания.** Полной выгрузки «всех шахмат Avito» за один
прогон не будет. Рабочий режим — несколько сотен лотов за проход,
несколько проходов в день по расписанию. За неделю накапливается
осмысленная база. Это ограничение задачи, а не настройки: любой, кто
обещает полный дамп Avito одной командой, либо не пробовал, либо
платит за прокси-пул.

**Сначала выясните диагноз, а не гадайте.** Строка `[miss] разбор не дал
лотов` одинаково выглядит и при блокировке, и при сломанном парсере, а
лечение у них противоположное:

```bash
python3 inspect_dump.py
```

Пройдёт по всем дампам в `debug/` и по каждому скажет прямо: БЛОКИРОВКА
(тогда парсер в порядке, вопрос только в темпе) или СТРАНИЦА ПРИШЛА, НО НЕ
РАЗОБРАНА (тогда это работа для Claude — покажите ему дамп).

**Если блокируют всё равно:**

```bash
python3 scrape.py --delay 40 --pages-per-query 2
```

Медленнее, но проходит. Терпение здесь дешевле изобретательности.

## Выход в моменте: прервать можно всегда

Данные пишутся в `items.jsonl` построчно с записью на диск после каждой
страницы, поэтому собранное не теряется никогда. Но нужен способ
остановиться, не убивая процесс на полуслове, — он есть.

| Что сделать | Что произойдёт |
|---|---|
| **Ctrl+C** один раз | сбор остановится после текущей страницы, конвейер дойдёт до шортлиста по собранному |
| **Ctrl+C** второй раз | выход немедленно; `items.jsonl` всё равно на месте |
| **`s` + Enter** на запросе при блокировке | остановиться сейчас и отранжировать собранное |
| **Enter** там же | продолжить (если была капча — сначала пройдите её в окне) |

Заранее ограничить прогон:

```bash
./run.sh --max-minutes 30      # остановиться через полчаса
./run.sh --max-items 500       # остановиться, набрав 500 лотов
```

Для cron это обязательно: иначе прогон может пересечься со следующим.

**Повторный запуск продолжает с места остановки.** Уже собранные `item_id`
читаются из `items.jsonl` и пропускаются, так что прерывать и
перезапускать можно сколько угодно — накопление идёт вперёд.

Важное следствие в `run.sh`: там намеренно НЕ стоит `set -e`. Досрочная
остановка и блокировка Avito — нормальные исходы, а не ошибки. Раньше
`set -e` убивал прогон целиком при блокировке на 4-й странице, хотя
`items.jsonl` был уже полон и его надо было просто отранжировать.

## Если в личном Chrome работает, а из скрипта блокирует

Это другой диагноз, чем блокировка по темпу, и лечится он противоположно.
Одинаковый IP, разный результат — значит Avito различает **отпечаток
браузера**, а не частоту запросов. Сбавлять паузы бесполезно: дело не в
них. Надо перестать выглядеть автоматизацией.

### Лучший способ: работать через ВАШ Chrome (режим `--cdp`)

Браузер настоящий, значит и отпечаток настоящий. Плюс ваши куки и уже
пройденная капча.

**1.** Закройте Chrome полностью (⌘Q, не просто окно).

**2.** Запустите его с отладочным портом. Отдельный профиль — чтобы не
трогать ваш основной:

```bash
# macOS
/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome \
  --remote-debugging-port=9222 \
  --user-data-dir="$HOME/chrome-avito" &
```

**3.** В этом окне откройте avito.ru и пройдите капчу, если появится.
Куки останутся в `~/chrome-avito` и переживут перезапуски.

**4.** Запускайте сбор с подключением к нему:

```bash
python3 scrape.py --cdp http://localhost:9222 --pages-per-query 3
```

Оставьте окно Chrome открытым на время прогона.

> Про безопасность: отладочный порт позволяет любому локальному процессу
> управлять этим браузером. Поэтому отдельный профиль, а не основной: в
> `~/chrome-avito` нет ваших паролей и сессий. Не логиньтесь там в важное.

### Проще, но слабее: настоящий Chrome без CDP

```bash
python3 scrape.py --channel chrome --headful
```

Запустит настоящий Chrome вместо сборки Chromium — другой набор кодеков,
Widevine, согласованный UA. Подозрений меньше, но своя автоматизационная
сессия, так что капчу придётся пройти заново.

### Что было сделано не так до этого

Подставлялся `user_agent` с `Windows NT 10.0` — при работе на macOS. При
этом `navigator.platform`, WebGL-рендерер и Client Hints говорили Mac.
Такое противоречие само выдаёт бота надёжнее, чем отсутствие спуфинга.
Теперь UA не подменяется вообще: браузер представляется сам, и это
согласованно. В `fetch_photos.py` UA привязан к реальной платформе.

### Граница

Полностью выиграть эту гонку нельзя: защиту пишут люди, которым за это
платят, и она обновляется. `--cdp` устойчив именно потому, что не
притворяется браузером, а является им. Если и он перестанет проходить —
значит Avito начал смотреть на поведение, и тогда вопрос снова в темпе.

## Промежуточный срез, не останавливая сбор

`items.jsonl` пишется построчно с сохранением на диск после каждой
страницы, поэтому читать его во время работы безопасно. В другом окне
терминала:

```bash
cd ~/claude_skills/avito-chess-hunter
python3 status.py                # срез на сейчас
python3 status.py --watch        # обновление каждые 30 сек
```

Покажет: сколько собрано всего, сколько за последние 5 и 30 минут
(растёт — значит сбор жив), сколько проходит порог, сколько отсеяно по
датировке, разбивку по запросам и топ кандидатов на текущий момент.

Полноценный шортлист тоже можно снять на ходу, сбор об этом не узнает:

```bash
python3 score.py items.jsonl --top 50 > snapshot.csv
```

## Калибровка фильтра

Веса в `score.py` — мои априорные догадки, не измерение. Пока вы их не
проверили, шортлист это черновик. Калибровка занимает минут двадцать и
стоит больше, чем лишние часы сбора.

### 1. Получить файлы

```bash
python3 score.py items.jsonl --top 100 --out top.csv        # просто топ, посмотреть
python3 score.py items.jsonl --calibrate --calibrate-n 60   # -> calibrate.csv
```

`top.csv` — что фильтр считает лучшим прямо сейчас.
`calibrate.csv` — выборка для разметки.

### 2. Почему выборка расслоённая, а не топ-60

Размечать только верх рейтинга — методическая ошибка. Так видно
ложноположительные (лишнее наверху), но принципиально не видно
**ложноотрицательные** — жемчужины, которым фильтр дал низкий балл. А они
дороже: лишнего кандидата вы отбросите за пять секунд, пропущенный лот
уйдёт навсегда.

Поэтому `calibrate.csv` берёт 40% из верхней полосы, 30% из середины и
30% снизу. Колонка `band` показывает, откуда лот.

### 3. Разметить

Откройте `calibrate.csv` (Numbers, Excel, LibreOffice — CSV с BOM, кириллица
не поломается) и проставьте в колонке `verdict`:

| Значение | Когда ставить |
|---|---|
| `gem` | хочу посмотреть всерьёз, возможно куплю |
| `maybe` | непонятно, но не мусор |
| `no` | мусор, новодел, дилер, не моё |

По вкусу коллекционера, без теории. Ваше «нет» — это данные.

### 4. Сверить

```bash
python3 score.py items.jsonl --eval calibrate.csv
```

Покажет таблицу точность/полнота по порогам, назовёт лучший порог и —
главное — перечислит лоты с вердиктом `gem`, которые фильтр отсеял.

### Честная граница

60 меток позволяют настроить **порог**, но не переобучить шесть весов:
данных слишком мало, получится подгонка под шум. Если ложноотрицательные
нашлись — пришлите файл мне, по ним видно, каких слов не хватает словарям
в `score.py`. Это точечная правка по конкретной причине, а не
статистическая подгонка, и она честнее.
